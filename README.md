# Mikhail Peryshkin — плёнка, Leica M4

Одностраничный сайт с двумя коллекциями: **чёрно-белой** и **цветной**.
Разделения по годам нет.

Концепция — смена среды. Чёрно-белое живёт на тёмном, как отпечатки в
проявочной; цвет — на тёплой бумаге, как печать из лаборатории. Между ними
полноэкранный кадр, на котором среда переключается. Единственный цвет в
интерфейсе — приглушённый красный неактиничного фонаря, и тот очень скупо.

Интерфейс на русском, имя в шапке — латиницей.

### Разделы

Сразу после заставки — оглавление: три строки со счётчиками кадров, клик ведёт
в раздел. Это обычные ссылки (`#bw`, `#color`, `#about`), поэтому работают
и без JS, и ими можно делиться.

1. **Black & White** — 43 кадра
2. **Color** — 26 кадров
3. **About** — камера и контакты

### Что умеет

**Липкая шапка** появляется, когда уехал экран-заставка: показывает текущую
коллекцию, переключает между ними и ведёт полосу прогресса по странице.
В цветной секции сама перекрашивается в бумажную.

**Листалка** открывается кликом по кадру:

| действие | как |
|---|---|
| листать | `←` `→`, клик по половине кадра, свайп на телефоне |
| зум 1:1 | клик по кадру, клавиша `Z` или кнопка `1:1` |
| панорама в зуме | тянуть мышью или пальцем |
| выйти из зума | `Esc` (первое нажатие снимает зум, второе закрывает) |
| прыгнуть к кадру | лента миниатюр внизу |
| поделиться | кнопка `Copy link` |

Ссылка вида `#bw/12` или `#color/07` открывает конкретный кадр сразу.

## Открыть

Двойной клик по `site/index.html`. Сервер не нужен — данные вшиты в
`site/assets/js/photos.js` как обычный скрипт, `fetch` нигде не используется.

Для проверки «как на хостинге»:

```bash
cd site && python3 -m http.server 8777
```

## Выложить на хостинг

Залить содержимое папки `site/` целиком. Никакой сборки не требуется.

## Что править руками

**Текст о себе** — в `site/index.html`, блок `about__lead`. Сейчас там
нейтральная формулировка про плёнку и M4; замени своими словами, так будет
лучше. Рядом `about__specs` — табличка камера / объектив / город.

**Контакты** — в `site/index.html`, блок `COLOPHON` внизу. Сейчас там заглушки:

```html
<li><a href="mailto:hello@example.com">hello@example.com</a></li>
<li><a href="https://t.me/username">Telegram</a></li>
<li><a href="https://instagram.com/username">Instagram</a></li>
```

**Ритм ленты** — массив `RHYTHM` в `site/assets/js/app.js`: сколько кадров
ставить в ряд. Единица — кадр во всю ширину, тройка — плотная строка.
Массив зацикливается.

**Потолок высоты ряда** — переменная `--cap` в `site/assets/css/style.css`.
Ряды выключены по ширине: `flex-grow` каждого кадра равен его соотношению
сторон, поэтому в ряду у всех одна высота и кадры не обрезаются.

**Сила зерна** — `opacity` у `.grain`. Это один SVG-шум, без картинок.

**Кратность зума** — `scale(2)` в функции `applyZoom` в `app.js`.

## Добавить фотографии

1. Положить в `Photo/Color BW/BW/` или `Photo/Color BW/Color/`. Папки по годам
   больше не используются — источник только эта папка.
2. Вписать имя файла в `ORDER_BW` или `ORDER_COLOR` в `tools/build_images.py`,
   в то место последовательности, где кадр должен стоять. Не вписанные файлы
   не пропадут — скрипт допишет их в конец и напечатает предупреждение.
3. Пересобрать:

```bash
tools/.venv/bin/python tools/build_images.py
```

Скрипт идемпотентен: пересобирает `site/img/` и `site/assets/js/photos.js`
с нуля. Оригиналы в `Photo/` он не трогает.

Порядок кадров задан вручную списками `ORDER_BW` и `ORDER_COLOR` — кадры
выстроены так, чтобы перекликались между собой, а не по алфавиту.

Фоны секций — `BW/1.jpg` и `Color/2.jpg` (заданы в `BACKDROPS`). Из галерей
они исключены, чтобы не дублироваться.

## Как собраны картинки

Pillow в локальном venv (`tools/.venv`, Homebrew не нужен): Lanczos-ресайз,
`UnsharpMask` после уменьшения — иначе зерно замыливается, а здесь оно и есть
содержание.

Чёрно-белая коллекция приводится к честному grayscale: часть плёночных сканов
тонирована. Цветная не трогается — там тон и есть содержание.

### Лестница размеров

Каждый кадр пишется в четыре ширины — 480, 960, 1440 и 2400 (константа
`LADDER`), и подключается через `srcset`. Браузер сам берёт нужную ступень
под ширину показа и плотность экрана.

Это важно: одного превью не хватает. Кадр во всю ширину ленты занимает около
1000 css-пикселей, а на ретине это 2000 реальных — без лестницы такой кадр
растягивался бы втрое и выглядел мыльным.

Атрибут `sizes` считается в `app.js` из доли, которую кадр занимает в своём
ряду. Оценка чуть щедрая — браузер иногда берёт ступень с запасом. Это
сознательный размен: лучше лишние килобайты, чем мыло.

Ступени выше оригинала не создаются: девять сканов меньше 2400px, для них
лестница короче, и это ограничение исходников, а не сборки.

Плюс один JPEG на кадр (ширина 1440) — запасной, подключается через `onerror`
для браузеров без поддержки WebP.

### Версия ресурсов

Сборка проставляет `?v=<штамп>` у css и js в `index.html`. Без этого
посетители с прогретым кэшем получили бы старые данные к новой разметке.

## Шрифты

Unbounded (заголовки) и Martian Mono (подписи, номера кадров) лежат локально
в `site/assets/fonts/` — сайт работает офлайн и переносится одной папкой.

Оба с настоящей кириллицей: сайт на русском, и шрифт без неё уронил бы
заголовки в системный. По этой причине сюда не годятся, например,
Space Grotesk, Anton и Bebas Neue — кириллицы у них нет вовсе.

Unbounded заметно шире большинства гротесков, поэтому кегли и трекинг по
всему сайту пересчитаны под него. Если менять шрифт — эти значения придётся
пересчитывать заново.

Латиница и кириллица лежат отдельными файлами и подключены через
`unicode-range`: латинская страница не тянет кириллический файл и наоборот.
Обновить:

```bash
bash tools/fetch_fonts.sh
```

Без сети сайт не ломается: в CSS прописан системный фоллбэк.
